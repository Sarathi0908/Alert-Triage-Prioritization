# Model #01 — Alert Triage & Prioritization (CSE-CIC-IDS2018, LightGBM)

LightGBM triage classifier over screened native NetFlow features, laid out in the
project's standard model-slot structure — the same one the UEBA (insider-threat)
slot uses.

The *model* is unchanged from the original: same algorithm, same 5 screened
features, same fitted operating point, metrics identical to the reference run.
What changed is the structure, the naming, and the fact that every number the code
used to hardcode now comes from `configs/`.

## 3 · Structural changes, not just renames

- **`build_model.py` was one 220-line script.** It is now a `LightGBMTriage` class
  (`fit` / `attack_probability` / `fit_threshold` / `verdict` /
  `shap_contributions` / `save` / `load`) plus a `PriorityScoreBuilder`, with
  orchestration in `pipeline.py`. That is the shape the UEBA slot uses.
- **`pipeline.py` runs in process.** It imports and calls; it does not shell out to
  seven scripts. One `run_training()` returns the metrics dict.
- **Charts are best-effort.** Every function in `plots.py` logs and returns `None`
  on failure, so a broken chart cannot lose you a completed training run.
- **`plots.py` styling was duplicated** in the model and EDA scripts; it now exists
  once.
- **A SIEM connector was added.** The model's decision is formatted into risk
  records with routing tiers and the HITL rule that a high-confidence flow is never
  auto-closable. `outputs/risk_index.jsonl` is the analyst queue — the top 5,000
  alerts by priority; the run logs how many were withheld, so the cap is not silent.

## 4 · Files that did not exist before

- **`requirements.txt`** — the original gap. Derived from this slot's actual
  imports, pinned to versions verified on 2026-08-12 under Python 3.14.2. It is
  **not** a copy of the sibling model's, which is wrong here in four ways: it lists
  `flask` (this serves on **FastAPI**), `shap` (explainability uses LightGBM's own
  `pred_contrib`), `seaborn` (nothing imports it), and **omits `pyarrow`**, which is
  mandatory because every entry point reads a parquet table.
- **`configs/`** — three YAML files. Seeds, hyperparameters, the 0.70 precision
  floor, the 0.70/0.30 priority weights, all screen thresholds, the API port and the
  Postman scenarios came out of the code into these.
- **`mlops/`**, **`tests/`**, **`pytest.ini`**, **`.gitignore`**, this file.

## 6 · Verified — 2026-08-12, Python 3.14.2

`py src/pipeline.py` ran green in ~66s and reproduced the reference run **exactly**:
ROC-AUC 0.9922 (train 0.9944, gap 0.0022), PR-AUC 0.9864, fitted threshold
0.144544, precision 0.7003, recall 0.9821, FN 1.79%, alert reduction 68.6%, and
`data/native_selected.json` + `data/feature_screen.csv` byte-identical to the
original. All §8 gates **PASS**. `py -m pytest -q` → **129 passed**.

API verified live: a real *DoS attacks-Hulk* flow → `p=0.999992`, ALERT, priority
86.5, decile 10, action `escalate`, destination `priority_queue`; a *Benign* flow →
`p=0.004291`, NORMAL, no priority or decile, destination `data_lake`.

**Two bugs the tests caught, worth recording:**

1. `fp_per_analyst_hour` is `(1 - precision) × 60/minutes_per_alert`, so at 5
   minutes it can never exceed 12 — the ceiling of 20.0 I first configured was
   **vacuous**. It is now 4.0, which binds at precision ≈ 0.667, just under the 0.70
   floor. The config notes that this gate is precision re-expressed as workload, not
   an independent signal.
2. A pandas float column cannot hold `None`, so unranked NORMAL flows reached the
   SIEM connector as `NaN` and `int(NaN)` raised. The connector now normalises
   `NaN` → `None`, which also matters because `NaN` is not valid JSON.

## 7 · Deliberate deviations from the UEBA layout

1. **`data/build_*_dataset.py` stayed in `data/`.** UEBA bootstraps through
   `_infra`; these are standalone builders that read an archive and write their
   parquet next to themselves. `src/data_source.py` still owns all *reading*.
2. **`src/config.py` degrades without `_infra/`.** The in-repo version raises at
   import if no `_infra/` sits above the slot. This tree has none, so
   `_find_repo_root` returns `None`, `HAS_INFRA` reports the mode, and `infra()`
   raises only when a shared-platform module is actually requested. The `_infra/...`
   paths in `mlops/*.yaml` are therefore aspirational here.
3. **One model module, not four.** UEBA composes two baselines and a forest; this is
   a single classifier plus a priority builder.

## 8 · Things worth knowing about the model

- **The threshold is fitted, not fixed.** The analyst queue is precision-constrained,
  so `fit_threshold` takes the highest-recall point that still holds ≥70% precision
  (0.1445 here) and stores it *inside* the bundle. The API reads it from there, so
  the served operating point cannot drift from the evaluated one —
  `tests/test_flow_triage_api.py` asserts exactly that.
- **Priority ranks alerts only.** Normal traffic is never ranked; `/score` returns
  `priority: null` for it. The blend interpolates against percentile grids captured
  at training time, also in the bundle, so one request gets the percentile it would
  have had in training.
- **Explainability needs no extra dependency.** `pred_contrib=True` is exact tree
  SHAP from LightGBM itself.
- **5 features is deliberate.** The dominance screen drops anything holding >45% of
  the gain (a dominator is a leak/memorisation risk) and anything under 1.5% (dead
  weight). `TCP_WIN_MAX_IN` went as dominant; `DURATION_OUT` was hand-excluded at
  0.93 solo AUC.
- **`Infilteration` is the weak class** at 0.70 recall against 1.00 for everything
  else — it is the blind spot the drift config watches, and the reason per-class
  recall carries its own gate.
- **The model trains on `ids2018_merged.parquet`** despite the CICIDS2017 filenames
  throughout the original. The 2017 table is kept as a second benchmark
  (`data.alt_dataset`) but nothing trains on it.
